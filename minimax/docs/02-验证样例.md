# 验证样例

本样例用于核对本作品的六项必做验收项。所有命令在 `minimax/` 目录执行。

---

## 一、任务描述

> 为 OrderFlow 的 `orderflow.refund` 模块实现 `SPEC-REFUND-014`：按退款原因决定运费是否可退，
> 优惠券按 `SPEC-PRICE-003` 分摊，并按 `SPEC-REFUND-020` 把单次退款金额限制为订单实付金额的 50%。
> 需要实现的符号是 `orderflow.refund.refundable_amount`。

业务工程：**OrderFlow —— 订单履约与退款服务**（`minimax/workspace/`），纯标准库、可运行、带测试。
本次要修改的接口行为：把 `orderflow/refund.py::refundable_amount` 从「未实现」补齐为
「按现行规格计算可退金额」。

## 四、操作步骤与预期结果

### 步骤 1：导入工程资料到 seekdb

```bash
python -m sddctx.cli import
```

**预期**：`规格条目 9 条，代码符号 32 个，测试用例 16 个`；`spec_item.search_text` 上存在
`FULLTEXT` 索引 `idx_spec_search`。

### 步骤 2：构造上下文（数据库实际参与）

```bash
python -m sddctx.cli context \
  --task "为 OrderFlow 的 orderflow.refund 模块实现 SPEC-REFUND-014：按退款原因决定运费是否可退，优惠券按 SPEC-PRICE-003 分摊，并按 SPEC-REFUND-020 把单次退款金额限制为订单实付金额的 50%。需要实现的符号是 orderflow.refund.refundable_amount。" \
  --out artifacts/context-pack.md --quiet
```

**预期**：

- 规格命中 `SPEC-REFUND-014 / SPEC-REFUND-020 / SPEC-PRICE-003 / SPEC-REFUND-001`；
- 「已失效的决策」小节列出 `SPEC-REFUND-012`（标注不得作为约束）；
- 代码符号首位是 `orderflow/refund.py::refundable_amount`；
- 测试清单包含 `tests/test_refund_quota.py` 的全部用例；
- 执行的 SQL 记录在 `artifacts/context-queries.log`，其中包含
  `MATCH(search_text) AGAINST (...)` 全文检索与按模块过滤的查询。

### 步骤 3：规格变更后重新导入（验证不是固定答案）

```bash
python scripts/verify_context.py
```

**预期**（全部为 `True`）：

- `required_specs_present`：必要规格齐全；
- `required_symbol_present`：目标符号命中；
- `target_tests_present`：目标测试用例 >= 6；
- `obsolete_spec_excluded_from_active`：已失效规格不出现在有效规格中；
- `obsolete_spec_marked_superseded`：已失效规格被单独标注；
- `spec_update_reflected`：把 `SPEC-REFUND-020` 的上限从 50% 改成 30% 并重新导入后，
  输出使用**更新后的**内容，且不再包含旧值。

### 步骤 4：任务状态保存与复用（模块重启）

```bash
# 另开一个终端：bash scripts/start_powercontext.sh

python -m sddctx.cli state save \
  --task "为 OrderFlow 的 orderflow.refund 模块实现 SPEC-REFUND-014" \
  --task-id "TASK-REFUND-014" \
  --done "已定位 orderflow/refund.py::refundable_amount 待实现" \
  --todo "实现 SPEC-REFUND-014 的运费可退规则" \
  --todo "运行目标测试与回归测试"

python -m sddctx.cli state show      # 另一个进程：读回
```

**预期**：`state show` 输出与写入内容一致（`task_id / done / todo / updated_at`）。

再执行一次 `sddctx context`，**预期**上下文包第 4 节出现上面写入的「已完成 / 待办」。

一键复核：`python scripts/verify_state.py`（输出 `artifacts/state-check.json`）。

### 步骤 5：修改前失败 / 修改后通过

```bash
python scripts/verify_before_after.py
```

**预期**：

```
[修改前] 目标测试退出码 = 1（期望非 0）
[修改后] 目标测试退出码 = 0（期望 0）
[修改后] 回归测试退出码 = 0（期望 0）
✅ 修改前失败 / 修改后通过，回归测试全部通过
```

- 修改前的失败原因必须是 `NotImplementedError`（目标行为未实现），
  **不能**是缺依赖、无法启动等环境错误（脚本会强制校验这一点）。
- 修改前后测试文件保持一致，脚本用 `snapshots/before/` 里的代码快照还原「修改前」状态。

日志：`artifacts/test-before.log`、`artifacts/test-after.log`、`artifacts/test-summary.json`。

### 步骤 6：MiniMax 参与代码修改

```bash
export MINIMAX_API_KEY=<你的 MiniMax API Key>
python -m sddctx.cli agent apply --task "…" --target orderflow/refund.py \
  --reference tests/test_refund_quota.py --reference orderflow/pricing.py --reference orderflow/models.py \
  --test-command "python -m pytest -q tests/test_refund_quota.py" \
  --record artifacts/minimax-run.json
```

**预期**：日志显示「已写入：orderflow/refund.py」，测试退出码 0；
`artifacts/minimax-run.json` 记录了请求摘要、模型原始响应与解析出的文件列表。

### 步骤 7：一键跑完全部检查

```bash
bash scripts/verify_all.sh
```

## 五、重置方法

```bash
bash reset.sh          # Windows: reset.bat
```

删除 `.data/`（seekdb 索引目录 + PowerContext 本地 SQLite 库），回到完全干净的起点。
重置后需要重新执行：

```bash
bash start.sh
bash scripts/start_powercontext.sh
```

PowerContext 的 Scope 与 Memory 条目随本地库一并删除；重新执行步骤 4 即可从空状态开始。
