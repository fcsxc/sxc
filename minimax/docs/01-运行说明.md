# 运行说明

本文档说明如何在**干净环境**中从零跑通本作品。全部命令在 `minimax/` 目录下执行。

---

## 一、环境要求

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Linux x86_64 / macOS / Windows | Windows 为兼容环境，已实测通过 |
| Python | 3.11+，推荐 3.12 | PowerContext 需要 SQLite >= 3.38，Python 3.12 自带 3.4x |
| 依赖安装 | `pip install -r requirements.txt` | 见下方「二」 |
| MiniMax 凭据 | 环境变量 `MINIMAX_API_KEY` | 仅在重放「MiniMax 修改代码」这一步需要；其余步骤不需要模型 API |
| 网络 | 安装依赖时需要 | 运行期不访问外网（除 MiniMax 调用） |

已验证版本：

- Python 3.12（推荐）/ 3.14（实测）
- `pylibseekdb==1.4.0.post2`（嵌入式 seekdb，Linux x86_64 / macOS arm64 / Windows x86_64）
- `powercontext[cli,server]==1.4.1`
- `pytest>=8.0`

---

## 二、安装依赖

```bash
cd minimax

# 1) 虚拟环境
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 2) 依赖
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

或者直接用一键脚本（等价于上面三步 + 导入 + 构造上下文）：

```bash
bash start.sh          # Windows: start.bat
```

---

## 三、启动 PowerContext（保存 / 复用任务状态）

PowerContext 以**模板模式**运行：SQLite 存储 + 基础记忆，**不需要任何模型 API Key**。

```bash
# 生成配置（无人值守，不需要交互式终端）
python scripts/init_powercontext_config.py

# 启动服务（前台；另开一个终端继续后面的步骤）
bash scripts/start_powercontext.sh        # Windows: scripts\start_powercontext.bat
```

服务默认监听 `http://127.0.0.1:8000`。若改用其它地址，请同步设置环境变量：

```bash
export POWERCONTEXT_URL=http://127.0.0.1:8000
```

> 说明：`powercontext config init --template` 需要交互式终端，脚本 `init_powercontext_config.py`
> 直接调用 PowerContext 自带的配置生成函数（`powercontext.cli.config.collect_configuration`），
> 产出完全相同的内容。

## 四、导入工程资料到 seekdb

```bash
python -m sddctx.cli import
```

预期输出：

```
规格条目 9 条，代码符号 32 个，测试用例 16 个
seekdb 统计：{'spec_item': 9, 'code_symbol': 32, 'test_case': 16}
```

- seekdb 数据目录：`.data/seekdb/`（嵌入式实例，随进程启停，不依赖外部数据库服务）
- 表结构：`spec_item` / `code_symbol` / `test_case`
- `spec_item.search_text` 上建有 **IK 分词器全文索引**（`FULLTEXT INDEX ... WITH PARSER ik`），
  检索时使用 `MATCH(search_text) AGAINST (...)`

## 五、构造开发上下文

```bash
python -m sddctx.cli context \
  --task "为 OrderFlow 的 orderflow.refund 模块实现 SPEC-REFUND-014：按退款原因决定运费是否可退，优惠券按 SPEC-PRICE-003 分摊，并按 SPEC-REFUND-020 把单次退款金额限制为订单实付金额的 50%。需要实现的符号是 orderflow.refund.refundable_amount。" \
  --out artifacts/context-pack.md
```

上下文包包含四节：**适用的规格条目 / 需要修改的代码文件与符号 / 用于验证功能与兼容性的测试 /
已完成事项、待办事项与已有验证结果**（第 4 节来自 PowerContext）。

## 六、用 MiniMax 完成代码修改（可选，用于完整重放）

```bash
export MINIMAX_API_KEY=<你的 MiniMax API Key>

python -m sddctx.cli agent apply \
  --task "为 OrderFlow 的 orderflow.refund 模块实现 SPEC-REFUND-014：……" \
  --target orderflow/refund.py \
  --reference tests/test_refund_quota.py \
  --reference orderflow/pricing.py \
  --reference orderflow/models.py \
  --protocol minimax --model MiniMax-M3 \
  --test-command "python -m pytest -q tests/test_refund_quota.py" \
  --record artifacts/minimax-run.json
```

- **凭据来源**：`MINIMAX_API_KEY` 环境变量；未设置时模块会自动复用官方 `mmx` CLI 已配置的
  `~/.mmx/config.json`（先执行 `mmx auth login` 即可）。
- **调用方式**（`--protocol`）：
  - `minimax`（默认）= 官方 HTTP API `POST {base}/text/chatcompletion_v2`；
  - `mmx-cli` = 官方 `mmx text chat --messages-file … --model …`；
  - `anthropic` = Anthropic 兼容的 `POST {base}/messages`。
  可用 `MINIMAX_BASE_URL` / `MINIMAX_MODEL` / `MINIMAX_PROTOCOL` 用环境变量覆盖。
- **模型**：实测 `MiniMax-M3`（HTTP API 与 `mmx` CLI 两种方式均可用）。
- 模型只允许修改 `--target` 指定的文件；其它文件（含测试文件）即使被模型输出也会被拒绝写入。
- `--test-command` 失败时，测试输出、静态检查出的**未定义名**与**签名不匹配**会作为反馈回灌给
  模型，最多重试 `--max-attempts` 次。

## 九、重置

```bash
bash reset.sh        # Windows: reset.bat
```

删除 `.data/`（seekdb 索引 + PowerContext 本地库），回到完全干净的起点；
再执行 `start.sh` 与 `scripts/start_powercontext.sh` 即可重新初始化。

## 十、已知限制

1. **PowerContext 服务需要单独进程**：上下文模块通过 HTTP API 访问它；服务未启动时，
   `context` 命令会打印警告并继续（状态一节为空），`state save/show` 会直接报错退出。
2. **MiniMax 凭据不随仓库提供**：`MINIMAX_API_KEY` 由使用者自行配置；未设置时模块会自动复用
   官方 `mmx` CLI 的 `~/.mmx/config.json`（先 `mmx auth login`）。缺凭据时第 2.3 节之外的
   步骤仍可完整运行。
3. **模型能力影响自动改码**：本次实测 `MiniMax-M3` 一次通过；较小的 `MiniMax-Text-01`
   无法稳定收敛到既有函数的正确签名（详见 `docs/05-MiniMax-开发记录.md`）。
   评审重放时建议同样使用 `MiniMax-M3`。
4. **Windows 为兼容环境**：PowerContext 官方标注 Windows 为 experimental，
   本作品在 Windows 上实测通过，但评审环境建议使用 Linux x86_64。
5. **seekdb 为嵌入式实例**：没有独立的数据库服务进程，数据随 `.data/seekdb/` 目录持久化；
   评审如需独立服务，可用 `pylibseekdb.connection_options()` 暴露的端点自建连接。
6. **上下文排序是相关度排序**：规格按「数据库全文得分 + 关键词命中 + 任务直接引用的规格编号 +
   适用模块命中」综合打分；不要求与参考实现排序完全一致。
7. **验证命令建议用 `--test-argv`**：`--test-command` 走 shell 拼接，可执行文件路径含空格时
   需要自行加引号，否则会出现「测试其实没跑」的假失败。
